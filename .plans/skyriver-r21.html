Build the model once at render creation. Pass it to attribute generation and CPU evaluation. Remove the seed-free global table cache. Use the existing avalanche hash, impostorHash, for separate motion channels. Do not use the weaker local CPU hash for new motion.

Speed and passing

freight  = 40  + 35 H(speed)
standard = 70  + 60 H(speed)
express  = 150 + 45 H(speed)
q(t)     = arc × L + speed × t
v(t)     = mod(direction × q(t), L)

Remove the longitudinal surge from these paths. Its derivative changes speed by up to 60.5 m/s. Keep small lateral and height motion.

Select convoy membership by the seeded density pulse. Use a shared pulse factor 0.70 + 0.15 H(convoyFactor). Give each member a small seeded speed difference. Fast cars use this signed passing offset:

pass(t) = sign × 12 × sin²(π × (t/T + phase))
T       = 16 + 16 H(passPeriod)

Convoy members use zero passing offset. Fast cars keep higher forward speed. This gives a continuous ±12 m passing movement without neighbour queries.

Forks

For each CPU stream, seed one or two fork intervals. A car selects each fork at spawn with independent hash bits. Bake four variants per stream: main, fork 0, fork 1, both. Eight streams, six unchanged GPU lanes, and one warp row require 39 table rows. The width remains 1601 samples. The table uses about 1 MB.

S(u) = u³ × (10 − 15u + 6u²), with u clamped to [0,1]
B(d) = S(d/600) × [1 − S((d − length + 600)/600)]
Cfork(v) = Cmain(v) + B(d) × (lateral, vertical)

Use total support length 1200–1500 m. This stays within the stated 800–1500 m range and permits two full 600 m ramps. Use lateral magnitude 60–120 m and vertical magnitude 30–60 m. Select the lateral sign from valid directions. Check the full row width, jitter, passing offset, and hull margin before accepting the fork.

Reserve both interchange ramp intervals for each existing interchange:

[at, at + 1100]
[at + L/2, at + L/2 + 1100]

Use wrapped intervals with a margin. Place forks and hop ramps outside these intervals. Keep fork and hop supports separate. Use bounded seeded placement. Fail model validation if placement cannot meet the rules.

One stream change per lap

Select 15% of normal stream cars for hops. This meets the 10–20% target. Apply the new hop model to medium and high traffic. Keep cars 0–113 on their current escort and chase rules.

Only connect streams with the same direction. Seed a fixed source/target pair. Use one transition per lap. Alternate the pair across successive laps:

n = floor(q/L)
p = mod(q,L)
s = S((p − hopStart)/hopRamp)
w = even(n) ? s : 1 − s
C = mix(CA(v), CB(v), w)

Use a 600–900 m ramp. The hop has period 2L. The target stays active at the lap boundary. The next lap starts on that target. A weight that resets to zero each lap would cause a teleport.

Blend complete canyon positions, including row offsets. Keep one seeded forward speed through the transition. Do not blend opposite directions.

GPU attributes and path parity

aImp   = logicalPath, arc, phase, appearanceSeed
aFlow  = row, effectiveSpeed, signedPassPeriod, hopRamp
aRoute = bakedRowA, bakedRowB, hopStart, reserved

Set bakedRowB = bakedRowA for cars without a hop. The physical row includes the branch choice. Rings keep their existing logical path IDs and pose code. R19.6 removes GPU free cars.

Store each canyon path texel as (centreX, centreY, slopeX, slopeY). Keep the warp row as (worldX, worldZ, cosHeading, sinHeading). Use the same linear sample lookup on CPU and GPU. CPU cars must also use the baked warp row. Exact warpCanyon and the GPU table are different paths.

For heading, include the branch and hop slopes:

C' = mix(CA', CB', w) + (CB − CA) × dw/dv

Add the passing offset derivative. Convert the result through the sampled warp. Use the normalized position derivative for lights, hull heading, and pitch. This prevents cars from facing along the original stream during a branch or hop.

For CPU free cars, set drift periods to 20 + 20 H(period) seconds. Derive heading from drift velocity and forward velocity. Reduce each home range by its drift amplitude and hull margin. This avoids a hard lateral clamp.

Verification

  • Hold out seeds from implementation. Include zero, negative, maximum int32, and several fixed ordinary seeds.
  • Check model equality for repeated seeds. Check prefix stability across car counts.
  • Check every fork endpoint, ramp endpoint, hop endpoint, and lap boundary at t ±0.001. Include negative time and skipped frames.
  • Check one completed hop per lap over at least four laps.
  • Compare actual GPU position output with CPU output at branch and hop boundaries. A second CPU formula does not prove shader parity.
  • Sweep every baked variant and every hop envelope at ≤8 m spacing against createMassField. Subtract the maximum hull radius.
  • Check forward speed separately from world speed. Canyon curvature changes world speed.
  • Keep the R19 450–750 m light band, tier prefix behavior, ring clearance, and draw count.

Required range interpretation

An 800 m total branch cannot contain two 600 m ramps. The proposal uses total support of 1200–1500 m. If total support must include 800 m, shorten each ramp to min(600, length/2). Another option defines the 800–1500 m value as the offset run between the ramps.

Strict express speed of 150–195 m/s cannot include a convoy at 70% of an in-band cruise speed: 0.70 × 195 = 136.5. Treat speed bands as normal cruise bands, with convoy reduction as an exception. Otherwise, clamp convoy factors to feasible values.
