# Collision-geometry toggle in the model viewer

> **For agentic workers:** Use the `execute-spec` skill to implement
> this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Stop showing the 20 `…-collision` GLBs as browsable gallery entries; instead expose them as a Collision toggle on their visual counterpart in the 3D viewer.

**Architecture:** Pairing is derived at runtime from the existing manifest by id suffix (`foo` ↔ `foo-collision`) — no manifest regeneration. Two pure helpers land in `catalog.ts` (unit-tested); `ModelGallery` filters collision entries out at load time and passes the paired collision entry down to `ModelViewer`, which swaps the loaded GLB behind a toggle button following the existing Turntable/Wireframe pattern.

**Tech Stack:** React 18, TypeScript, three.js via @react-three/fiber + drei (`useGLTF`), vitest, Playwright.

---

## Overview

The Pirate Nation showcase's Models tab (`tools/pirate-nation-showcase`) renders whatever `runtime/models.json` contains — 375 entries, of which 20 are collision meshes. They share categories with visual models, so they pollute search results, category counts, and the grid with near-duplicate cards, making the catalog harder to browse. The useful information — "what does this model's collision geometry look like?" — belongs in the previewer as a swap flag, not as a separate catalog entry.

## Requirements

1. Gallery grid, search, category chips, and the "All"/search-placeholder counts cover only visual models — collision entries never appear as browsable cards.
2. Every visual model that ships a `…-collision` counterpart gets a **Collision** toggle button in the viewer controls; models without one (e.g. Kraken) show no such button.
3. Activating the toggle swaps the rendered geometry to the collision GLB (camera refits to its bounds); deactivating restores the visual GLB. Turntable/Wireframe state persists across the swap; the toggle itself resets when a different model is selected.
4. Pairing is derived at runtime from the loaded manifest by id suffix; a collision entry with no visual counterpart is ignored (no crash, no toggle).
5. `README.md` and the touched components' header comments describe the new behavior.

## Non-goals

- Editing or regenerating `runtime/models.json` or deleting collision GLBs (external extractor output; fragile to hand-edit).
- Further browse-UX changes (default sort order, subcategory grouping, grid layout) — see Open Questions.
- Avatar Lab, sprites, audio, or overview tabs.
- Unit-testing the R3F canvas itself (no WebGL in jsdom); viewer behavior is covered by e2e.

```ts
/** Collision GLBs ship as separate catalog entries with a `-collision` id
 * suffix, next to their visual counterpart (upstream `Collision/` folders). */
export function isCollisionModel(entry: Pick<PirateNationModelEntry, 'id'>): boolean {
  return entry.id.endsWith('-collision')
}

/** Maps each visual model id to its collision counterpart, for models that
 * ship one (`foo` ↔ `foo-collision`). Orphan collision entries are skipped. */
export function buildCollisionIndex(
  models: PirateNationModelEntry[],
): Map<string, PirateNationModelEntry> {
  const ids = new Set(models.map((entry) => entry.id))
  const index = new Map<string, PirateNationModelEntry>()
  for (const entry of models) {
    if (!isCollisionModel(entry)) continue
    const visualId = entry.id.slice(0, -'-collision'.length)
    if (ids.has(visualId)) index.set(visualId, entry)
  }
  return index
}
```

## Open Questions

- Is the remaining browse friction solved by de-duplicating collision entries, or do we also want a follow-up on default sort (e.g. largest-footprint-first) or finer grouping? Deliberately deferred — revisit after using the cleaned-up grid.
- Collision GLBs are baked at a much smaller scale than their visuals (e.g. the shipwright collision mesh is ~13 units vs ~112 for the visual). The swap replaces the visual and the camera refits via `fitKey={activeEntry.id}`, so collision geometry renders correctly standalone; overlaying both at matched scale is a non-goal. If scale-matched comparison is ever wanted, the catalog's `normalizedShift` metadata is the place to start.
- Review-cycle note: the reviewer asked for an e2e assertion that the camera refits on swap. Rejected — FitCamera's refit is not observable from the DOM, and WebGL readback is out of scope for a smoke spec. The `waitForRequest` on the collision GLB covers the observable behavior.
