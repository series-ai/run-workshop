Turn limit hint diagnosis

The fault recorded below was fixed after this run. The controller now waits for finalization and checks pending input before showing the hint. Two regression tests cover a queued room event and an actual wait for the player.

Cause

The hint is stale when a room event waits behind an active model run. The fire event set a pending room input in observeEvents(). The current run then ended with max_turns. The controller set needsInstruction to true and wrote “He pauses to listen.” The final callback then cleared running and called drain(). The queued fire input started at once. The new run set needsInstruction to false and continued physical work.

Live evidence confirms the order. The cap note was written at game time 359.8007. At 371.6007, the controller had status acting and needsInstruction: false. The cloth placement completed at 374.5002. Shard extraction and suture preparation then continued without a new player command.

Smallest safe fix

  1. Store the max_turns result until the run finalizer.
  2. Check whether a pending input will drain.
  3. Set the hint and write the journal note only when no input will drain.
  4. Add a test with a queued room event and a capped first run.
