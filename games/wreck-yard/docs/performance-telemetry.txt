Wreck Yard performance telemetry
=================================

This recorder is local and opt-in. It does not send data to a server. The
recorder is inactive until a caller starts it.

The game installs the console API at `window.__WRECK_YARD_PERF__`.
It stays inactive during normal play.
On a phone, open Pause, then Performance capture. Select Record performance.
Resume play. Repeat the action. Release the tool and wait for recovery.
After at most 60 seconds, open Pause and select Save report. Use the phone
share sheet when file sharing is available. Other browsers download JSON.
The report stays local. Starting a new recording replaces the previous one.

Start a short capture from the console with:

    window.__WRECK_YARD_PERF__.start({ capacity: 32768, maxDurationMs: 30000 })

The default capacity is 32768 records. The maximum capacity is 65536 records.
The default duration is 30000 ms. The maximum duration is 60000 ms. The
recorder stops when the duration ends, when the caller stops it, or when the
page exports the report. The capture writes records to fixed-size numeric
typed arrays. It overwrites old records when the ring is full. The report gives
the total record count and the number of overwritten records.

Stop and export a capture with:

    const report = window.__WRECK_YARD_PERF__.stop()

The browser report also records its capture date, deterministic version,
engine identity hash, user agent, logical CPU count, and viewport values.
`viewportAtStart` is read when recording starts. `viewportAtExport` is read
at the first export. It is not the automatic-stop viewport. No URL, account
ID, or token is collected.

The report uses milliseconds for time and bytes for memory. It contains raw
records, p50/p95/p99 quantiles, minimum, maximum, and mean values. The recorder
computes summaries after it stops. Raw quantiles describe only retained raw
records. They do not describe the complete capture if the ring overwrites.

The additive `timeline` field keeps one-second summaries for the full capture,
independent of the raw ring. It has at most 60 bins. Each phase has count,
total, mean, and maximum duration. Each counter has count, minimum, maximum,
mean, and last value. Empty bins have null frame bounds. These are not
quantiles. Phase durations belong to their start bin. A phase that crosses the
recording deadline retains its actual duration, then stops recording.
If it is an inner phase, the final enclosing phase can be absent.
`elapsedMs` can exceed the deadline for that last blocking call. Bin offsets
stay within the configured duration. Starting allocates the fixed numeric
summary arrays. Export creates report objects after capture stops.

The report has these record groups:

* CPU phase durations for frame pumping, simulation, checkpoints, encoding,
  rendering, occlusion, crates, portals, and post-processing.
* Numeric samples for simulation, checkpoints, encoding, occlusion, crates,
  portals, wake work, WebGL resources, and owned buffer estimates.
* Input timestamps for local `event`, `sample`, `apply`, and `renderSubmission`
  stages. Each input needs one local sequence number. `perfInputEvent(simFrame)`
  creates and records an event sequence. Keep that number beside the same
  temporary local input. Use it for later stages. Do not put it in deterministic
  simulation input or network state.
* Optional JavaScript heap values at capture start and stop. The report says
  `unavailable` when the browser does not expose heap values.
* WebAssembly bytes when the caller reports `memory.wasmBytes`. The report says
  `unavailable` when no value is reported. The production SDK may not expose
  this value.
* Optional GPU query durations from WebGL2 and
  `EXT_disjoint_timer_query_webgl2`.

Input latency values require all four stages in this order:

    event -> sample -> apply -> renderSubmission

The report keeps the first timestamp for each stage and each sequence. It marks
an incomplete or out-of-order timeline and gives it no latency values. The
`renderSubmission` value measures work up to renderer submission. It does not
measure display or presentation latency.

The GPU helper uses asynchronous WebGL2 timer queries. It reads a query result
only after `QUERY_RESULT_AVAILABLE` is true. It never calls `gl.finish()`.
It uses a fixed query pool of 16 queries by default. The pool limit is 64. It
does not create a query for every sample. It allows one active query at a time.
End each scope before the next scope. Call `poll(frameId)` after all active GPU
scopes end. A `valid`, `disjoint`, or `unavailable` status is recorded for each
GPU result. The report also gives a lost query count. Stop, dispose, and WebGL
context loss delete query objects.

When capture is inactive, phase and count calls return before they read the
clock or allocate a record. Starting a capture allocates its bounded rings and
one duration timer. Export stops capture before it allocates report objects or
sorts values.

Run the browser captures
------------------------

Start Vite on port 4481. Run these commands from games/wreck-yard:

    npm run dev -- --host 127.0.0.1 --port 4481 --strictPort
    node scripts/profile-performance.mjs my-capture
    node scripts/verify-performance-input.mjs
    node scripts/verify-performance-occlusion.mjs
    node scripts/verify-performance-memory.mjs
    node scripts/verify-performance-memory.mjs --restart

Set AUDIT_URL to use another local server. Results go to
test-results/performance. The scripts close Chrome when they finish.
The mobile layout uses Android browser settings on the host GPU. It does
not measure a phone.

Use the separate development page for native function names and memory:

    PERF_PATH=/scripts/performance-profile.html node scripts/profile-performance.mjs native-capture --cpu-profile

The production entry does not import the profile WASM artifact. The
production bundle can contain the names of profile API fields without
containing the profile binary. Verify the actual base64 artifact, not
only those field names.

Read the report
---------------

CPU scopes are inclusive. Do not add a parent scope to its child scopes.
sim.nativeStep includes SDK world.step and world.latest.
sim.physicsStep and sim.physicsLatest measure those public calls separately.
sim.players, sim.stackWake, sim.impacts, sim.crateBreak, sim.fractures,
sim.cooling, and sim.worldRead separate game work. fracture.carve includes
heat painting and carving. fracture.split includes component filtering and
sorting. fracture.cook measures fragment body preparation. fracture.edit
measures game state replacement and native remove/add edits.
Contact, impact, pending-cut, actual-cut, removed-voxel, fragment, and hot-body
counts help compare cut and recovery intervals. input.moveX/input.moveZ are
absolute axis values. Page scale and camera FOV/zoom distinguish page gestures
from camera changes. JavaScript heap samples are browser-dependent. It includes SDK
portal preparation and output work as well as the native solver.
portal.plan includes planning and portal scene submissions.
post.ao measures the separate ambient-occlusion pass. Ink runs inside
post.composite with bloom, cavity, and the color grade.

GPU samples time separate scene submissions and post passes. Stencil
surface draws outside those scopes are not counted. Do not sum p95 values
from separate passes and call the result a frame p95. Disjoint and pending
queries are unavailable samples. They are not zero-duration samples.

webgl.ownedBufferBytes counts unique geometry, index, and instance array
backing buffers. It excludes texture and render-target memory.
webgl.postTargetBytesEstimate estimates the declared HDR, depth/stencil,
MSAA, bloom, and AO target formats and sizes. It excludes driver padding,
shadow maps, scene textures, and the browser backbuffer. It is not total
GPU memory. WebGL does not expose exact device allocation totals.

The memory-soak script waits for the 256-frame rollback history to fill.
It samples after explicit garbage collection outside timed captures.
It checks steady resource and checkpoint counts plus the native heap
plateau. A short heap increase during startup does not establish a leak.
WASM heap bytes are retained high-water capacity; the engine need not
return them to the operating system.
The runner still keeps 256 logical saves. Since the 2026-10-16 checkpoint
repair, checkpoint.live and checkpoint.peak count only the recent native
saves, with a limit of 32. Older saves use raw JavaScript physics buffers.
checksumBytes can import one temporary native save. This scratch save is
not part of the retained-save counters. checkpoint.spill measures the
serialization and release of an older native save. It runs before capture.
JavaScript heap totals and native heap totals must both be checked. A lower
native count alone does not show lower total memory use.
The restart mode checks four real matches. It fills the rollback history
in each match. The first restart can release starting-view GPU resources
and grow native high-water capacity. The next three matches must keep
the same checkpoint, GPU resource, and native heap counts.

Input submission uses a successor snapshot so the applied tick is on
both sides of interpolation. Continuous input sequences are queued.
Paused events remain incomplete. This is a conservative submission bound.
It is not display latency.

Interaction and performance audit: 2026-10-16
---------------------------------------------

Start the local game on a free port. The audit used port 4490:

    npm run dev -- --host 127.0.0.1 --port 4490 --strictPort
    AUDIT_URL=http://127.0.0.1:4490 MONKEY_OUT=test-results/monkey-perf/my-desktop node scripts/verify-yard-monkey.mjs --seed 5311,9187
    AUDIT_URL=http://127.0.0.1:4490 MONKEY_OUT=test-results/monkey-perf/my-mobile node scripts/verify-yard-monkey.mjs --seed 5311 --mobile

The script uses real keyboard, pointer, HUD, and touch input. It uses the
existing look control for repeatable aim. It does not move bodies or set
simulation state. Targeted phases cover movement, thrust, tools, grabs,
throws, cuts, portal passage, storage, the buggy, pause, focus handling, and
restart. Each seed also drives a random action block. Use --only with a
phase name to isolate a failure. Use --actions to set 1 to 200 random actions.

Each output directory contains summary.json, an action journal, per-segment
recorder exports, and images. The journal records an action before its input
and after its observed result. Session errors, non-finite poses, and stopped
frames stop the drive. Legal tool refusals remain in the journal. Timing
reports include simulation ticks per wall second. A smooth display can still
hide a slow simulation. A failed phase remains failed in the final result.

Headless tab activation did not deliver blur or visibility events in this
environment. The harness records that limit. A separate DOM blur event
checks the clear-input handler. It does not prove native window-focus
delivery. A mobile layout on this host does not prove phone performance.

Run timed probes one at a time. The portal diagnostic uses a paused scene
after frame 360 and alternates normal and skipped style passes:

    AUDIT_URL=http://127.0.0.1:4490 PORTAL_WIDTH=2560 PORTAL_HEIGHT=1440 node scripts/profile-portal-cost.mjs my-portal-capture

Skipped style passes change the image. They only isolate cost. They are
not a product option. The final repair keeps the style and limits raster
work to the portal rectangle, with filter borders and stencil clipping.
Per-view GPU p50 fell from 3.04/3.72 ms to 1.185/1.182 ms in the two normal
captures. CPU submission p50 rose from about 1.0/0.9 ms to 1.6/1.6 ms.
Frame intervals stayed near the 16.7 ms display limit. This is a measured
GPU gain. It is not a measured whole-frame gain or a CPU gain.

readWorldState now reuses the step's portal output. It still reads current
body motion and filters removed native IDs. It avoids a second full latest
read and its material/contact objects. Exact 400-frame idle and falling
goldens match. Both traces keep all 256 logical saves and dispose all native
resources. gameAfter p50/p95 fell from 2.762/5.568 to 0.278/0.599 ms at rest
and from 1.729/3.834 to 0.231/0.427 ms while falling. Host load was lower in
the after run. The full tick difference cannot be assigned to this change.

The raw checkpoint byte buffers remain a memory cost. The audit does not
establish a phone memory budget. Native retained bytes, WASM capacity,
JavaScript buffers, process RSS, and uncollected garbage are different values.

The final validation passed 452 simulation tests, 50 portal checks, 71
gravity visual checks, and four production browser tests. The browser tests
include four warm solo starts with capture and frame progress. The full
interaction drive completed 62 desktop actions over two seeds and 38
mobile-layout actions. After the final controller repair, fresh desktop and mobile-layout focus,
pause, and restart checks also passed. These six actions have separate

A production capture test found a real start fault that the drag-look drive
did not expose. A forwarding trace records accepted capture, connecting,

with pause at frame zero. The controller now keeps connecting during offline

The comparison also found a remaining SDK cost. Four isolated common-API
