Historical rc.39 investigation
The sections below record the original proposal and its evidence.
The proposal changed revision 1. The published repair uses revision 3.
Do not apply the historical revision 1 patch to rc.40.

Fault 1: dynamic ground places the capsule too low
- dynamicGroundUnderKcc uses kccFeetOffset but omits kccSlopeClearance.
- Static grounding already includes this clearance.
- A dynamic voxel prop tilted by 0.03 rad is enough to cause the fault.
- The controller reports grounded. Its capsule still intersects the prop.
- resolveKccHorizontalMotion rejects the full move and both axis moves.
- Requested walking becomes zero movement in every tested direction.

Fault 2: revision 1 cannot recover an existing intersection
- A capsule can intersect a prop after a landing near an edge or corner.
- The center ground probe can select the lower floor.
- The capsule side still intersects the prop beside it.
- Revision 1 rejects walking away as well as walking into the prop.
- Revision 2 recovers these edge cases, but still overlaps tilted props.
- A revision 2 switch alone does not resolve both faults.

Isolated SDK fixture
- Character radius: 0.4 m. Half height: 0.5 m. Skin: 0.005 m.
- The test uses the same expanded capsule as the controller.
- Floor top: -0.86 m. Prop top: about 0.64 m.
- Prop shapes: box, cooked voxels, and a hollow compound roof.
- Tilt: 0, 0.03, and 0.1 rad. Static and dynamic controls are included.
- Edge drop: x=1.4 m beside a prop with half width 1.28 m.
- Corner drop: x=z=1.4 m beside that prop.
- Settle for 60 ticks. Then move 0.04 m per tick for 14 ticks.
- A clear walking direction must travel 0.56 m and remain grounded.
- A direction into the prop must stay blocked.
- No walking frame may leave the expanded capsule intersecting a solid.

Repair
- File: docs/patches/syncplay-rc39-kcc-standing.patch
- Target: packages/syncplay/src/movement3d-revision1.ts
- Apply slope clearance to dynamic ground and reattachment.
- Recover the stored capsule pose before input movement.
- Do not recover a requested forward pose through an obstacle.
- Limit recovery to four passes. Sweep each correction against other solids.
- Preserve ignored bodies, sensor rules, layers, and sorted collision filters.
- Use native contact normals for ground and recovery filter candidates.
- Count the added native queries.

Limits
- This is a repair proposal, not a published SDK fix.
- Four passes do not guarantee escape from arbitrary deep containment.
- Recovery can remain blocked if there is no clear space for the capsule.
- Revision 1 query counts and checksums change.
- Release it as a new SDK artifact. Update controller baseline fixtures.
- Upgrade the game identity with the SDK. All peers must use that artifact.
- Run the SDK controller, portal, and checkpoint suites before publication.
