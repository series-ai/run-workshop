RUN controller input
====================

The game uses Game SDK 5.28's RundotAPI.gamepad API. It waits for ready(), then
checks isSupported(). It reads getGamepads() once per existing input frame.
It does not read navigator.getGamepads() separately. The SDK selects browser,
Steam, iOS, or Android input through its host handshake.

Controls
--------

Left stick       Move. Drive and steer while in the buggy.
Right stick      Look. Rotate the camera in Orbit.
Right trigger    Hold the gravity gun or torch action.
Left trigger     Punt or throw.
A                Jetpack. Exit the buggy with the jetpack.
X                Use. Enter or exit the buggy. Press a nearby button.
B                Drop a held body.
Left bumper      Select the gravity gun.
Right bumper     Select the torch.
Select           Enter or leave Orbit.
Start            Pause or resume.

In Orbit, left stick Y changes camera distance. The current camera limits
still apply. Near a lift panel, Dpad Down/Left/Up/Right selects G/1/2/3.
Near the storage reset control, X requests Restack. It does not also send Use.
The lift and reset use the existing AttractionRequest path.

Menus
-----

Dpad or left stick moves focus. A selects. B returns. Left and right adjust
a focused sound slider. Pause starts with Resume selected. Only the top menu
accepts navigation. A nearby lift panel does not take movement input.

Select Enter code in Pause to open the room-code keypad. Select six letters
or digits. Delete removes one character. Clear removes the draft. Join moves
to that room. B closes the keypad and returns to Pause.

Controller play does not request pointer lock or fullscreen. The start menu
remains until confirmation. Mouse, keyboard, and touch remain available.
The controller menu hides the Fullscreen entry control. A frame-polled
controller action cannot supply browser user activation. Exit fullscreen
remains available when fullscreen is active.
Controller activity changes the hints. Pointer or keyboard input restores
those controls. A connected idle controller does not hide touch controls.

State and ownership
-------------------

The input owner keeps the selected controller's source, index, and device ID.
A disconnect or owner change clears input. A controller used for play opens
Pause if it disconnects. A different pad must first reach neutral input.

The game clears input on gate transitions, browser blur, hidden state, and
RUN pause or sleep. Host pause, host sleep, browser focus, and visibility are
independent conditions. A browser focus event cannot clear a host pause.
Resume and Awake each clear only their own host condition.

Gameplay requires neutral controls before it re-arms. Fresh menu actions
remain available while a gameplay trigger is held. Held Start, A, or B does
not become a second press when a menu opens. A held stick or Dpad must return
to neutral before it navigates the new menu.

Short action presses remain queued until Syncplay samples the actual input.
The queue clears on pause, disconnect, or suspension. Movement stays in the
existing integer input schema. Look uses a radial dead zone and a bounded
angular rate. There is no simulation schema, identity, or dependency change.

The game owns its input state and lifecycle subscriptions. It removes its
subscriptions on unmount. It does not destroy the SDK-owned controller API.

Startup
-------

The initial room request starts in a microtask. React StrictMode cancels its
first effect before that task runs. This prevents two initial room requests.
The local SDK authority can remove a newer room membership when an older
request completes late. Its removed connection can keep an open socket after
the empty room stops. The game avoids the duplicate startup request. This
change does not repair the SDK server's connection cleanup.

Verification
------------

Use the standard local authority:

  npx playwright test e2e/controller.spec.ts --workers=1

The browser fixture replaces the device boundary. It keeps the real SDK,
WebSocket authority, runner, and Yard physics runtime. It checks the actual
sampled input and native player movement. Evidence is in test-results/controllers/.
Browser device emulation does not prove physical controller or native RUN
host behavior. DOM blur/focus injection checks the browser event boundary.
The native host suspension contract also received a source review.

On 17 October 2026, all seven controller browser checks and all seven existing
UI checks passed in one run. The initial page sent one room-create request
under React StrictMode. The keypad joined two real peers at 390 px. The 57
existing gate, match, seat, startup, touch-room, and input checks also passed.
The production build passed with the published Syncplay rc.54 package.
Desktop and 390 px Pause and keypad images received an independent review.
A final browser walk reached the storage controls through controller movement.
X advanced the native reset frame without sending Use. Dpad Up set the lift
target to floor 2 and started motion. The run had no page errors. A separate
final check confirmed that controller menus do not offer capture entry.
