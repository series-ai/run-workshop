New rc.56 regression
--------------------

The public createPhysicsInstalledRuntimeAdapter3D restore path leaves the
facade latest() cache stale. The real-WASM repro uses one body and one tick:

  Capture frame 0.
  Advance the runtime to frame 1.
  Read world.latest().
  Restore frame 0 through runtime.restore(saved).
  Read world.latest() again.

rc.55 returns runtime/native/latest frames 0/0/0. The check exits 0.
rc.56 returns runtime/native/latest frames 0/0/1. The check exits 1.
The rc.56 result is the same object returned before restore.
Both runs release owned native resources.

The facade cache is cleared for facade mutations, but the attached controller
restores raw state and portal state without clearing the cache. ensureReadable
checks access but does not check the cache frame or revision. Our custom
YardSim restore uses the facade and clears the cache. Thus the app suite
does not cover this SDK integration path.

Run from games/wreck-yard with a new output path:

  node scripts/repro-syncplay-latest-restore.mjs --sdk /path/to/package --out test-results/latest-restore-new.json

-----------------------------------------------

Native checkpoints now share static slabs. Dynamic caches and events stay
per checkpoint. The in-memory representation changed. The wire snapshot
versions, ABI, digest revision, and 160 MiB module limit did not change.
Cross-version checkpoint import was not tested.

The new static sharing reduces native retained storage in this fixture.
Serialized older JS saves still contain full state. Runner-level history
controls remain unchanged. The prior network recovery, snapshot target,
ordered seat context, and intentional leave requests remain open.
