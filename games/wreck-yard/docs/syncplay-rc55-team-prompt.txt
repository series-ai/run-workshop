3. Slow-client recovery sends stale input: confirmed fresh rc.55 wire evidence.

Run two real local peers. Apply CDP 6x CPU slowdown to one peer for 6 s, then reset
to normal. Keep focus active and the menu closed. At one aligned wall-second,
the authority was tick 1439 while the client sent inputs for 432-533. All 105
confirmations it processed that second substituted its own input. Public ready
was true while about 900 frames behind. It accumulated 30.5 s of rollback work.

A short reverse-path control showed zero movement on both peers after slowdown
ended. The frame gap recovered only after 27.671 s. Movement worked afterward.
That run recorded 24.1 s resimulation and 1398 own-input substitutions. The game's
pacing already uses targetLeadTicks 2/maxStepsPerPump 2 and input delay 1-3 ticks.

Ensure current input reaches the authority while old frames catch up. Bound
confirmation/rollback/catch-up work without changing canonical results. Add a
regression test for input delivery, neutral release, eventual checksum parity,
and recovery latency under controlled stalls. Expose authority frontier,
catch-up phase/backlog, snapshot selection, and relevant work timings through
supported diagnostics. RTT, rollback durations, applied/predicted frames, and
ownInputSubstitutions already exist; extend those instead of duplicating them.

4. Snapshot target contract: source-confirmed, still unchanged in rc.55.

authority-room.js requires snapshot.tick === pendingTransfer.targetTick.
networked-client.js treats requested minFrame as a lower bound, skips an
unavailable exact checkpoint, and can offer a later tick. The authority then
rejects it as snapshot-target-tick-mismatch. Both modules match rc.54 bytes.
Earlier local rc.54 logs showed these rejections and transfer timeouts.

The fresh rc.55 aged-room case successfully transferred snapshot 3600 with
sessionFrame 3601. That success does not test the missing-exact-checkpoint path.
Use one request/donor/authority contract with bounded refusal, rotation, or
retargeting. Test one donor missing the exact checkpoint while retaining a
later one, another donor able to satisfy the target, and a late client joining
from the validated snapshot plus contiguous input tail. Preserve checksum quorum.
