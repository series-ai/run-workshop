Package changes and game adoption
--------------------------------

Thirteen of 584 files changed. Changes cover native physics, checkpoints,
serialization, browser SHA-256, authority rooms, dev authority, and room
transport. All public declarations match rc.57. The runner and networked
client match rc.57. No new physics API call is required.

The rc.57 seat context and runner retention options remain available.
Wreck Yard still ignores the third runtime step argument and uses default
history settings. Canonical seat cleanup and explicit history limits remain
application work. These APIs were not adopted during this release check.

Checkpoint storage and memory
-----------------------------

The four-player storage drive reaches 600 frames. It retains 256 logical
saves and at most 32 retained native captures. Checksum import briefly
uses a 33rd slot. Old-state decode, replay, checksum, and encoded output
match exactly. Native ownership returns to zero. Stable and busy runner
drives each reach 600 frames, retain 256/32 logical/native saves, and
release all saves on disposal.

Peak raw JS physics buffers: 183433538 bytes, 174.94 MiB.
Native retained high-water: 23642332 bytes, about 22.55 MiB.
Tick including capture p50/p90: 22.341/25.390 ms.
Capture/conversion p50/p90: 0.993/1.221 ms.

Raw JS history size is unchanged from the rc.57 sample. The newer sharing
and serialization code does not compress or share older exported byte
saves. The native ceiling remains 160 MiB. These timing samples are not
an ABBA storage comparison. Memory metrics overlap and must not be added.
No leak or phone performance claim follows.

Checkpoint mutable fields now compare against the shared slab. Changed
fields receive checkpoint-owned storage; equal fields can share. Sentinel
offsets distinguish an empty field from a shared field. This includes
joints, forces, fluids, surface velocities, and material frames. Legacy
geometry is checkpoint-owned. Snapshot versions and physics/world ABI
values remain unchanged. This does not prove cross-version continuation.

SHA-256 check
-------------

The pure-JS hash now reads full input blocks directly and uses small tail
and scratch buffers. Node normally uses node:crypto, so app tests alone
do not grade the browser implementation. A direct pure-JS check compares
42 cases, with 84 repeated calls, against Node crypto. It covers padding
boundaries, input lengths from zero to one million bytes, nonzero-offset
views, reverse length order, and input preservation. All cases pass.
The separate real-browser check below exercises the fallback and prepared
writer branches.

Leave and networking source changes
-----------------------------------

Transport close now sends a client.left close message before room.leave().
Repeated close calls do nothing. Send errors are ignored; no acknowledgement
or retry is added. The new authority removes deterministic membership and
guards repeated leave. Rejoin can call onPlayerJoin when a former slot has
no current mapping.

The new dev authority also calls protocol.kick to remove local platform
membership. Game SDK 5.28.0 already provides the required source methods.
Wreck Yard already closes its transport through runner stop, so it needs
no new leave call. Both local client and authority must use rc.59.

Production close-to-kick handling exists at the rc.59 release commit:
server/mp-room-server/src/rooms/SyncplayAuthorityGameRoom.ts, lines 721-724.
It forwards the envelope, decodes close, and calls protocol.kick. The local
venus checkout has an older wrapper at a different HEAD. An initial read
of that checkout did not represent the release. The release-commit source
corrects that initial finding. Its deployed server version and hosted
behavior remain unverified.

Slow-client scheduling, recovery diagnostics, exact-target snapshot
donation, unavailable refusal, and donor rotation match rc.57. The
confirmation loop still has no per-call work or time limit. Missing-target
donor rotation still needs a focused real protocol test.

Browser and leave checks
------------------------

All six serial headless cases pass in about 2.8 minutes. They cover the
three normal local multiplayer flows, six-second 6x CPU stall plus aged
room, Chrome touch movement/release, and WebKit startup/taps. Both peers
use the actual rc.59 runtime identity and the normal dev authority.

The first flow measures about 60 rendered Hz and 29.83 confirmed Hz.
Interpolation changes positions within the same discrete frame.
Post-clear reverse movement reaches 9.626 m on both peers. Both runners
report live with backlog 0 by the first neutral check requested two
seconds after CPU clear. This is a sample, not an exact recovery latency
or a worst-case work guarantee.

Aged-room departure takes 151 ms; rejoin takes 1204 ms. The focused normal
lifecycle case measures 336/565 ms for departure/rejoin. Local explicit
leave therefore removes membership promptly in these cases. Unexpected
socket-loss grace and hosted deployment were not separately tested.

Snapshots 3480/sessionFrame 3481 and 3600/sessionFrame 3601 transfer and
decode successfully. No unavailable refusal or failed-donor rotation
occurs. That source branch remains outside this runtime coverage.

Wire and page errors are empty. The aged-room guest and Chrome touch
reports each contain one generic resource 404 without a saved URL.
A single short follow-up startup probe reproduces /favicon.ico 404 in
console location and resource timing. The app has no favicon file or icon
link. This is an app asset issue, not evidence of an SDK defect. The two
original entries remain unattributed; the probe is a candidate explanation,
not proof of their exact source. No page errors occur in the probe.

Browser SHA-256 check

Native phase timing includes output work. WASM memory is not reported.

Desktop touch emulation does not establish physical-phone performance.
