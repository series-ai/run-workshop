Wreck Yard performance pass
===========================

Baseline commit: feba1066. It contains the complete game integration,
Returns portals, 400-box storage bay, and elevator.

Game changes
------------

The renderer reuses the subscribed render result. It no longer interpolates
that result twice per frame. Stationary body poses also reuse their vectors.

Crates write instance matrices only when the pose or visibility changes.
At rest, writes fall from 872 per frame to zero. The measured crate upload
scope mean falls from about 0.096 ms to 0.014 ms on this host.
The storage and Returns batches have separate bounds. The portal camera
submits 129,742 triangles instead of 362,670. All 436 crates remain in the
simulation and renderer. Delayed uploads retain all pending changed ranges.

The occlusion volume excludes bodies outside its conservative bounds.
Distant moving crates no longer force local volume rebuilds. Independent
checks compare every byte with the full voxel-kit algorithm in 24 cases.
The output stays exact at every boundary, after motion, after rotation,
and after a cut.

Portal materials share their original textures. The portal clip registry
uses weak references. It keeps reused materials valid after React cleanup.
Native body name and sorted ID data are cached until topology changes.

The graphics tiers, shadows, lighting, ink, AO, bloom, crate count, colliders,
and gameplay rules are unchanged.

Measurements
------------

Real Chrome used an Apple M5 Max with a 1440 x 900 drawing buffer at DPR 1.
The Android 844 x 390 low-quality layout used the same host GPU. It does
not measure a phone. Host load ranged from about 14 to 53. These samples
cannot establish a general frame-rate guarantee.

The high-quality storage view has GPU medians of about 1.16 ms for the
main scene, 1.05 ms for AO, 1.27 ms for bloom, and 1.68 ms for the composite.
These are separate asynchronous query scopes. They omit some stencil
surface work. They are not a complete GPU frame percentile. Lighting and
post effects remain a material part of GPU cost.

CPU simulation spends most time inside SDK world.step and world.latest.
The named native profile identifies box collision geometry and contact
response preparation as the main work. SDK optimization is a separate
last step. The final response-only SDK repair is PR #5367. It reduces
resting-step medians by 17.4%, 14.5%, and 2.3% in three paired native runs.
It adds no measured native memory. Collapse timing is mixed. The change
preserves exact state and public contacts in 390 frames plus two 360-frame
kinematic-contact traces. All 119 focused native tests pass. CI and review
remain required before publication. The game still uses published rc.40.

After the 256-frame rollback history fills, a stationary 52-second check
keeps 257 live checkpoints, 186 textures, 240 geometries, and 70 programs.
The profile artifact's native heap stays at 114,425,856 bytes (about 109 MiB).
Retained JS heap after explicit GC goes from 102,972,320 to 104,260,080 bytes.
This short stationary check does not prove leak-free long sessions or
constant memory during destruction.

Four real matches also check restart cleanup. The first restart releases
starting-view GPU resources and grows native capacity by 256 KiB. The
next three matches each retain 257 checkpoints, 206 geometries, 50 textures,
69 programs, and 114,688,000 native bytes. Retained JS heap varies with GC.
This check proves a short restart plateau. It does not prove long-session
memory stability during repeated destruction.

Unique scene geometry and instance backing buffers use about 2.2 MiB.
Declared high-tier post target formats and MSAA use an estimated 82 MiB.
These estimates exclude shadow maps, scene textures, driver padding, and
the browser backbuffer. WebGL does not expose total GPU allocation bytes.
The production bundle excludes the complete profile WASM base64 artifact.
Profile API names can still occur in error messages and accessors.

Verification
------------

All 346 native game tests pass. TypeScript, identity, build, seven live
checks, and the complete attraction route pass. Browser E2E passes 3 of 4.
The pre-existing style-vista ink threshold still fails. Its threshold was
not reduced.

Independent Chrome checks prove correct GPU matrix data after two culled
instance changes, clip uniforms on late-added and reused materials, and
continuous input through actual SDK-decoded application. Sixty mouse moves
produce complete input timelines. Paused events remain incomplete.

The recorder has bounded numeric rings, bounded query objects, explicit
stop and clear, overwrite counts, and unavailable GPU states. It sends
nothing to a server. Normal play leaves it inactive.

Reproduction commands and report limits are in performance-telemetry.txt.
Hardware, load, raw phase summaries, and browser proofs are retained in
performance-evidence.json. Raw captures remain in test-results/performance.
